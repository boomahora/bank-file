# The six, and the twenty left out

## Why the record is short

A record that takes a quarter of an FTE to maintain does not get maintained. The six rows are
the ones that exist nowhere else retrievable. Everything below is deliberately excluded
because it already lives somewhere authoritative, and copying it creates a second version of
the truth that goes stale.

## The six

| Row | Why it is here |
|---|---|
| Waivers and concessions | Agreed in an email, by a person who may have left. Expires quietly |
| Pricing agreed outside the schedule | Contradicts the document on file, so the document is misleading on its own |
| Service commitments | Said in a meeting. Survives only if somebody wrote it down |
| Open promises | Visible only by reading a thread to the end and noticing no reply |
| Derived deadlines | Computed from two facts in one document. Appears in no document and no system |
| Why this bank | Reconstructed from memory at every review, differently each time |

## Left out, and where it lives instead

| Not in the record | Where it already is |
|---|---|
| Covenant levels and test dates | The facility agreement. Tracked anyway because the auditors ask |
| Facility size, margin, commitment fee | The facility agreement, clauses 2 and 8 |
| Maturity dates | The same agreement. The bank will raise it a year out anyway |
| Account inventory | The portal |
| Signatories | The account opening file and the bank's own records |
| Standard published fees | The fee schedule |
| Balances and transactions | The treasury system or the portal |
| Daily positions | The treasury system |
| Cash pool structure | The pooling agreement |
| Payment file formats | The implementation documentation |
| Cutoff times | The bank's published service terms |
| KYC refresh status | The bank chases this. They have more at stake than you do |
| FX rates and spreads | The dealing platform, unless a spread was agreed by email, which makes it a concession |
| Credit ratings | Public |
| Entity legal names | The group structure chart |
| Tax IDs | The group's own records |
| Portal user list | The portal's own access review |
| Contact phone numbers | A contact list, which is not a context layer |
| Statement format in use | Worth knowing once. Put it in the sources table, not a row |
| Service incident history | Only worth a row once it becomes a promise to fix something |

If a user wants one of these in the record, add it. The point is that nobody has to, and a
record that starts at six rows gets built this afternoon rather than next quarter.

## The one exception worth adding

Where a bank has agreed something about an excluded item, that agreement becomes a concession
row. A waived KYC requirement, a cutoff time extended in writing, a spread confirmed by email.
The row captures the agreement, not the underlying data.
